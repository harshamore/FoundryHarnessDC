# Constitution → mechanism mapping

The Foundry constitution (`trial-run/.specify/memory/constitution.md`, 11
principles) constrains the system's *design*, not just its prompts. This
table is the running record of where each principle is actually enforced in
code — updated as each notebook/module lands. "Not yet built" means the
principle applies to a piece that hasn't been implemented in this phase.

| Principle | Mechanism | Where |
|---|---|---|
| I. Evidence Over Assertion | `FindingStore.assign_verdict()` resolves every citation against a caller-supplied `resolver` before accepting `true-positive`; an unresolved citation force-demotes to `needs-review`, with the mismatch recorded in the report. The resolver is now the real Indexer (`IndexStore.symbol_exists()`), not the Substrate section's hand-typed stand-in, and the Triager's `assign_verdict` tool binds it as a closure the model can't see or influence — it supplies citations, the tool decides. Also now rejects a bare verdict with no `investigation_report` at all (FR-054): "a verdict without an investigation report MUST be rejected" | `src/foundry/substrate/finding_store.py`, real resolver in `src/foundry/indexer/store.py`, tool wrapper in `src/foundry/triager/tools.py`; proved in `tests/test_indexer.py::test_real_resolver_wired_into_evidence_gate`, live-agent-shaped in `tests/test_triager.py::test_assign_verdict_tool_demotes_fabricated_citation`, FR-054 in `::test_assign_verdict_rejects_empty_investigation_report` |
| II. Surface Only What Survives | Both Detector subagents' `tools` lists have no path to a human-visible output — only `queue_candidate`, which writes to the internal finding store, never an issue tracker. High-volume, low-precision candidates are the expected, correct behavior at this stage; nothing reaches a human until a Triager promotes it. The Triager itself surfaces nothing new either — `assign_verdict` only ever updates the internal finding store's `verdict` column. The Reporter is the only future role with a human-facing write tool | `src/foundry/detector/tools.py`, `src/foundry/triager/tools.py`, proved structurally in `tests/test_detector.py::test_detector_tools_shape` and `tests/test_triager.py::test_triager_tools_shape` (only `list_candidates`/`get_candidate`/`assign_verdict` exist, nothing that writes anywhere else) |
| III. Liveness By Heartbeat, Never By Clock | `WorkQueue.claim_next()` only reclaims a row whose `leased_until` has passed; nothing reclaims on wall-clock agent runtime | `src/foundry/substrate/work_queue.py`, proved in `tests/test_finding_store.py::test_stale_lease_is_reclaimable` / `::test_fresh_lease_is_not_reclaimable` |
| IV. Claims Are Atomic And Mortal | `claim_next()` is a single `BEGIN IMMEDIATE` transaction that re-checks its own WHERE clause on the UPDATE. Extended to a second, more general concurrency problem found live in two stages: DeepAgents can dispatch several tool calls from one LLM turn on real threads, all sharing one connection. First a bare `BEGIN IMMEDIATE` from two threads on the same connection raised "cannot start a transaction within a transaction" (the Cartographer's five write tools). Locking only the transactional writes wasn't enough — Python's `sqlite3.Connection` turned out to not be safe for truly concurrent access even for plain reads, reproduced as `InterfaceError` and a nonsensical `IndexError` from read-only tool calls. `lock_for(conn)` (one *reentrant* lock per connection, shared by every store on it) now guards the *entire body* of every method in every store that touches a shared connection, reads included, not just transactional writes | `src/foundry/substrate/db.py::lock_for`, applied to every method in `work_queue.py`, `finding_store.py`, `indexer/store.py`, `cartographer/store.py`, `budget.py`; proved under real concurrent threads sharing one connection in `tests/test_finding_store.py::test_concurrent_claims_never_double_claim` (separate connections, unaffected) and `::test_concurrent_queue_candidate_on_shared_connection_does_not_collide`, `tests/test_cartographer.py::test_concurrent_section_writes_on_shared_connection_do_not_collide`, `tests/test_indexer.py::test_concurrent_reads_on_shared_connection_do_not_corrupt` (shared connection, reads and writes) |
| V. The Provider Is The Rate Arbiter | The Indexer, Cartographer, Detector, and Triager sections each make one real OpenAI call per demo, but always a single top-level request (rule-sweep and the Triager may each make several tool calls within that one turn, not truly parallel top-level requests). Not yet built: no internal concurrency cap below OpenAI's actual limit, rely on LangChain's retry/backoff. Lands meaningfully once multiple *subagent instances* run concurrently (the Full Pipeline section) | — |
| VI. Coverage Before Yield | `BudgetGovernor.should_stop()` is a strict conjunction: `coverage_complete AND yield < threshold` (or a hard spend cap); low yield alone never returns `True` while coverage is incomplete | `src/foundry/substrate/budget.py`, proved in `tests/test_finding_store.py::test_low_yield_alone_does_not_stop_when_coverage_incomplete` |
| VII. Exploited Means Demonstrated | Not yet built — lands with the Validator subagent. Source-only phase: the `mark_exploited` tool simply does not exist until a testbed is configured (degraded mode, FR-066) | — |
| VIII. Fingerprints Are Stable Under Edit | `fingerprint()` hashes `(normalized_path, symbol, vulnerability_class)` only — never a line number or snippet | `src/foundry/substrate/finding_store.py`, proved in `tests/test_finding_store.py::test_requeueing_same_identity_deduplicates_despite_edited_description` |
| IX. Sandbox By Infrastructure, Not By Prompt | **Explicitly out of scope for the Colab phase** — flagged as a real gap, not faked. Addressed later via `deepagents`' `permissions`/`backend` (defense in depth) plus real container/network isolation once a testbed exists | — |
| X. The Operator Outranks Every Agent | Not yet built — lands with the Orchestrator (final notebook): `mark_coverage_complete` and `override_verdict` tools registered with DeepAgents' `interrupt_on`, requiring explicit operator approval | — |
| XI. Persist Atomically | Every substrate write goes through `BEGIN IMMEDIATE` / `COMMIT` (or SQLite's autocommit for single-statement writes with WAL); nothing is ever deleted-then-rewritten. `SecurityMapStore.write_section()` follows the same delete-then-insert-in-one-transaction pattern as `FindingStore`/`IndexStore` | `src/foundry/substrate/db.py`, `finding_store.py`, `work_queue.py`, `src/foundry/cartographer/store.py` |

Principles II, V, VII, IX, X depend on the LLM-agent layer (Indexer onward)
and are not testable without it — they're listed here as commitments this
build owes itself, not as claims already proven.
